# pdfcraft-embed

The embed build: PdfCraft's page view as a WebAssembly module that a host page mounts on its own
`<canvas>` and drives through one typed API, `EmbeddedEditor` (`pdfcraft_embed.d.ts`). This version
has view mode only: the page view with its own page navigation, zoom and find. Nothing edits,
saves, prints or opens files: the engine refuses changes (`Session::set_view_only`) and command
dispatch refuses everything but find, page display and zoom. Ctrl/Cmd+C copies the selection.

## Build

```sh
packaging/embed/package.sh   # dist/release/pdfcraft-embed-<version>.zip and .zip.sha256
```

It needs the `wasm32-unknown-unknown` target, `wasm-bindgen` at the version in `Cargo.lock`
(`cargo install wasm-bindgen-cli --version <it> --locked`, or `WASM_BINDGEN=…`), binaryen's
`wasm-opt` at the version in `packaging/embed/tools.env` (`WASM_OPT=…` names a binary; the script
refuses any other version and runs `wasm-opt -Oz`), cargo-about at the version in
`packaging/embed/cargo-about.env`, `jq` and `python3`. The version is this crate's own, not the
app's (`packaging/embed/package.sh --print-version`); release tags are `embed-v<version>`.

The zip holds, at its root:

| File | What |
|---|---|
| `pdfcraft_embed.js` | generated glue (ES module) |
| `pdfcraft_embed_bg.wasm` | the editor |
| `pdfcraft_embed.d.ts` | generated TypeScript declarations |
| `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`, `ATTRIBUTION.md` | PdfCraft's licences and attribution |
| `licenses/` | the licence texts of the third-party assets compiled into the module: Lucide icons (ISC), Inter, JetBrains Mono and Dancing Script (OFL 1.1), egui's default fonts (Ubuntu Font Licence, Hack, OFL 1.1 for Noto Emoji, MIT for emoji-icon-font), the Foxit standard-14 fonts and Adobe CMaps (BSD-3-Clause), and hayro's colour profiles (MIT, CC0); plus `OFL-<family>.txt` for each craft-fonts family when built with `CRAFT_FONTS_DIR` |
| `THIRD-PARTY-LICENSES.txt` | the licence notices of the Rust crates compiled into the module (generated by cargo-about): one section per licence text with the crates that use it, the NOTICE files those crates ship, and the Rust standard library's notices from the build toolchain |
| `SHA256SUMS` | the SHA-256 of every file above |

`THIRD-PARTY-LICENSES.txt` covers the embed crate's dependencies for `wasm32-unknown-unknown`
(`about.toml`, `packaging/embed/about.hbs`; no build scripts or tests), written by
`packaging/embed/third-party-licenses.sh`, which CI also runs alone. It fails on a crate whose
licence is unknown or not accepted (the accepted list must equal `deny.toml`'s allowlist), and on a
crate whose notice still shows a placeholder such as `<copyright holders>`: give that crate a
`[<crate>.clarify]` section in `about.toml` that points at the licence file naming its holder, or,
when none exists, list it with the reason in `packaging/embed/about-placeholder-allowlist.txt`. A
clarification fetches the upstream file at the package's commit, checked against a SHA-256, so a
release needs network access and a changed upstream file fails the package until reviewed. Needs
cargo-about at the version in `packaging/embed/cargo-about.env` (CI installs a checksummed
binary with `install-cargo-about.sh`; elsewhere `cargo install cargo-about --locked --features
cli --version <it>`), plus `jq` and `python3`.

The zip is reproducible: its bytes depend only on the toolchain and tools (the pinned Rust
toolchain, `wasm-bindgen`, `wasm-opt`, cargo-about), the commit and the dependencies locked in
`Cargo.lock`, not on the machine, user or checkout path (fixed timestamps under `TZ=UTC`,
byte-order file lists under `LC_ALL=C`, mode 644, no extra attributes or folder entries). The
module records the source path of each panic location; the script rewrites those paths with
`--remap-path-prefix` (registry and git crates to `/cargo/registry/src` and
`/cargo/git/checkouts`, the checkout to `.`) and fails if the module or its glue still holds
`CARGO_HOME`, the checkout path or the home folder.

The script sets `CARGO_ENCODED_RUSTFLAGS`, which cargo prefers over every other source of
rustflags, so it carries over the caller's `RUSTFLAGS` (or the wasm target's or `build`'s
environment variable) and refuses to build while a cargo config file on the checkout's ancestor
path or in `CARGO_HOME` sets rustflags that could apply to the wasm build, because those would be
replaced without a word: `[build]` (also `build.rustflags`), `[target.wasm32-unknown-unknown]`
(also dotted or quoted) and any `[target.'cfg(...)']` section (a cfg expression may match wasm32
and the script cannot evaluate it). Rustflags for another target triple, such as a host linker
under `[target.x86_64-unknown-linux-gnu]`, never reach this build and are allowed; pass flags
meant for the wasm build in `RUSTFLAGS`. `packaging/embed/rustflags-guard.sh` holds the check and
`packaging/embed/test-rustflags-guard.sh` tests it.

### Reproducing a release

To rebuild a release's zip and compare it with the published `.zip.sha256`:

1. Check out the tag cleanly (`git clone`, or `git checkout embed-v<version>` in a tree with no
   changes).
2. Use the Rust toolchain the workflows pin (their `toolchain:` lines): `RUSTUP_TOOLCHAIN=1.95.0`,
   with the `wasm32-unknown-unknown` target.
3. Install `wasm-bindgen-cli` at the version `Cargo.lock` locks for `wasm-bindgen`
   (`awk '/^name = "wasm-bindgen"$/ { getline; print; exit }' Cargo.lock`), with `--locked`.
4. Install binaryen at the version in `packaging/embed/tools.env` (123); its SHA-256 for the Linux
   x86_64 release is there too (`packaging/embed/install-binaryen.sh` does it on that platform).
   `package.sh` refuses another `wasm-opt`.
5. Install cargo-about at the version in `packaging/embed/cargo-about.env`
   (`packaging/embed/install-cargo-about.sh`), and have `jq` and `python3`. Releases are built with
   `CRAFT_FONTS_DIR` unset; set it only to rebuild a release that names craft-fonts licences in
   `licenses/`.
6. Run `packaging/embed/package.sh`, then compare `dist/release/pdfcraft-embed-<version>.zip.sha256`
   with the release's file, and run `packaging/embed/verify-zip.sh` on your zip.

Honest status: the path check has been run on a macOS build. Equality has not yet been checked
between two machines, two checkout paths, or macOS and the Linux runner that builds the release,
so a build elsewhere may differ in bytes (compare the files inside the zip:
`unzip -p <zip> SHA256SUMS` lists each file's hash) until someone has compared them.

### Releases

A tag `embed-v<version>` runs `.github/workflows/embed-release.yml`: the build (uncached, so no
earlier run's outputs reach the release), a check of the zip with `packaging/embed/verify-zip.sh`,
then a GitHub release holding `pdfcraft-embed-<version>.zip` and its `.zip.sha256`. The release
job alone holds the write token and the right to attest. `Packaging lint` runs shellcheck and the
self-tests of the packaging scripts (`packaging/embed/test-verify-zip.sh`, crafted zips the
verifier must refuse, and `packaging/embed/test-rustflags-guard.sh`); `Embed licences` generates
the licence notices on pushes to the `*-embed` branches.

`verify-zip.sh` extracts nothing. It requires the `.sha256` to be one line naming this zip with
its hash, the entry names to be exactly the files listed above (plain relative names: no absolute
path, `..`, backslash or folder entry, at most 100 characters, no two differing only in case) and
`SHA256SUMS` to list each of them once, and it hashes every entry streamed out of the zip. A host
can run it on a download.

The release job also attests the zip and its `.sha256` file with GitHub artifact attestation
(signed SLSA build provenance, `actions/attest-build-provenance`). The checksum only shows that
a file is consistent with itself; the attestation shows which repository, workflow and tag built
it. A host verifies a downloaded zip before trusting it, with the GitHub CLI:

```sh
gh attestation verify pdfcraft-embed-<version>.zip --repo rsysapp/pdfcraft
```

The command fails for a file that was not built by this repository's release workflow.

## Behaviour a host page relies on

- Call the module's default export (`init`) before `EmbeddedEditor.mount`. `mount` resolves after
  the first frame, so a canvas in a hidden tab resolves when the tab shows.
- Set the listener before `open`: events with no listener are dropped. Events arrive after the
  frame that produced them. `opened` is followed by `pageChanged` for the first page.
- `open` replaces the document and clears marks and any jump still waiting. A broken file, or one
  that needs a password, answers `openFailed`; there is never a password prompt.
- Text jumps and marks match with whitespace runs as one space, Unicode compatibility forms
  folded (NFKC), curly quotes and dashes straightened and case folded, within one page. A text
  jump waits until the pages it searches have their text; a newer jump replaces a waiting one.
- `selection` is sent each time a selection settles (button released, or a keyboard selection),
  not on every frame, and again when it equals the one reported before: a press and release on the
  page view (a page or the pasteboard beside it), or the same passage selected again, settle it
  anew, since the host hides its toolbar on input. A press on the zoom controls, the page display
  menu, the scrollbar or the find field does not. Nothing is told without input: if the selection
  is off screen when the button is released, it is not told when a scroll brings it back.
  `x`, `y` are CSS pixels from the canvas's top-left at the end of its last line.
- A found text jump selects its match, so it shows highlighted. That selection is the editor's
  own and is never reported, not even after a press that leaves it as it is; selecting it again by
  hand is a person's selection and is. The editor moving the view (a page jump, a later text jump,
  its page buttons, a find step) or opening a document clears it without an event, and answers a
  selection it had reported with `selectionCleared`. A jump that finds nothing leaves either.
  While the canvas has keyboard focus, Ctrl/Cmd+C after a found jump copies the jumped text, as the
  document spells it, and reports nothing.
- Malformed arguments throw a `TypeError` and change nothing, from every method: `mount` with
  anything but an `HTMLCanvasElement` or with malformed options (its promise rejects), `open` with
  anything but a `Uint8Array` and a string, `jumpTo`, `setMarks` and `setTheme` with a wrong shape,
  a non-integer or negative number, NaN or an infinity, or a bad colour, and `setListener` with
  anything but a function.
- `destroy` stops the runner; later calls do nothing. Dropping the object (`free()`) destroys it
  too. Either may be called from any handler, including one eframe triggers inside a frame (its
  text agent's `focusin`/`focusout`, or the `blur` of an opened link): the host hears nothing more
  from the call on, and the runner is torn down once the frame has returned.
- Put a timeout on `mount` in the host page: it resolves after the first frame, which a canvas
  that never shows (or a failed start) does not produce.
- Each `mount` installs eframe's panic hook. Mounting and destroying repeatedly in one page chains
  hooks, one per mount.
- Events raised before `setListener` are dropped.
- Keyboard: eframe keeps Tab on the canvas. Wrap the canvas in an element with a capture-phase
  `keydown` listener that moves focus on Tab and Shift+Tab.
- Nothing is stored in the host page's storage.
- Hide the host's selection toolbar on `opened` and `openFailed`, and on any pointer, wheel or key
  input in the canvas's wrapper: a reported selection's `x`, `y` go stale once the page scrolls.

## Limits

- `setMarks` keeps the first 2,000 marks (`MAX_MARKS`) and ignores the rest.
- Passages are at most 256 KiB of UTF-8 raw (`MAX_RAW_PASSAGE_BYTES`, checked before anything is
  folded) and 10,000 characters once folded (`MAX_NEEDLE_CHARS`): a longer mark is skipped, a
  longer text jump answers `jumpNotFound`. A mark that is empty once folded is skipped.
- Page numbers and occurrences above 2^32-1 saturate to 2^32-1, so they are out of range for any
  document: the jump answers `jumpNotFound`, the mark is skipped. Negative or fractional numbers
  throw.
- `open` takes files of at most 100 MiB (`MAX_OPEN_BYTES`). A larger one is answered, in order,
  `openFailed` ("This file is too large or complex to be shown here.", as the Word editor says) and
  changes nothing else: the open document, its marks and any waiting jump stay. Its bytes are never
  copied into the module. An empty array, which is how a detached or transferred buffer reads, is
  answered `openFailed` as a broken file. After `destroy`, `open` copies nothing.
- `open` requires a `Uint8Array` from the host page's own realm (not from another frame or window):
  anything else throws a `TypeError`, as does an array whose buffer cannot be read.
- `mount` requires a canvas from the realm the glue was loaded in: a canvas from an iframe or a
  pop-out window is not an `HTMLCanvasElement` there and is refused with a `TypeError` (the promise
  rejects). Load the glue in the window whose document holds the canvas.
- A text jump or mark without a page loads every page's text layer, so its cost grows with the
  page count; a page-scoped one loads that page alone. Matching costs O(page text × passage) per
  page searched, on the frame.
- What a malformed call throws echoes the strings the host sent (a mark's id or colour, a value
  that failed to parse): show it as text, never as markup. `openFailed` carries a fixed, plain
  message: "This file is damaged or isn't a PDF and can't be shown." for a file the engine cannot
  read, "This file is password-protected and can't be shown here." for one that needs a password,
  and the too-large message below. The engine's own reason goes to the browser console as a
  warning.
- The editor's warnings reach the browser console at warn level (`mount` sets eframe's logger to
  warn): a file that could not be opened, and a page whose text layer or rendering failed
  (`page N text: …`, `page N: …`). The page warnings carry the page number and a fixed reason (the
  page does not exist, or its page box is empty or invalid, with its size), never document text.
  The page renderer's own diagnostics are compiled out of this build (hayro without its `logging`
  feature).
- The command and event queues are unbounded: the host page is trusted not to flood them.

## Crashes

A Rust panic aborts the WebAssembly module: there is no unwinding on wasm32. A stack overflow or a
failed allocation traps it the same way. After a trap the editor sends nothing more and later calls
may throw. The host therefore treats "no `opened` or `openFailed` within its timeout after `open`",
or a call that throws, as a failure: it shows its own failure panel and discards the whole module
instance, never mounting on it again.

A trap leaves the instance's memory as it was: locks held, the stack pointer not restored. And
`init` returns the same cached instance. A new editor mounted on it can therefore crash at once or
hang until the host's timeout. So after a failure the host:

1. calls `destroy()` on the failed editor inside a `try`, since after a trap it may throw;
2. drops every reference to that editor and to the module it came from;
3. for the next mount, loads a fresh instance: a new `import()` of the glue under a new URL (its own
   module record, for example `pdfcraft_embed.js?attempt=2`), then that glue's `init`, which makes
   a new WebAssembly instance with its own memory. The compiled `WebAssembly.Module` may be reused
   (pass it to `init` as `module_or_path`); only the instance must be new. A recreated iframe or
   worker that loads the glue is a fresh instance too.

`destroy()` throws nothing by itself. It can throw only after a trap, or after `free()`
(wasm-bindgen refuses any call on a freed object). Both are cases where the host's `try` is needed
anyway.

On a `mount` timeout, keep the promise and `destroy` the editor if it resolves late. eframe paints
on animation frames, which a browser does not run in a hidden or background tab: there `mount`'s
first frame, and the `opened` or `openFailed` that answers an `open`, wait until the tab is visible
again. A host therefore pauses its `open` and `mount` timeouts while `document.hidden` is true
(resuming them on `visibilitychange`), or a document opened in a background tab is taken for a
crash.

## Branding

Built without the `brand` feature of `pdfcraft-ui-egui`: the bundle carries none of the ArtCraft
logo images and shows no ArtCraft names or links (`docs/brand/LICENSE-brand.txt`). The package
script fails if a logo asset key (`bytes://artcraft-`) is in the module. Build `pdfcraft-embed`
with `-p pdfcraft-embed` alone: building it together with the apps (`--workspace`, or
`-p pdfcraft-web`) unifies the `brand` feature back on. `NOTICE` in the zip says the build is
based on PdfCraft by the ArtCraft team.
